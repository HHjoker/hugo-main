## 为什么需要基准测试？

### 单元测试 vs 基准测试

| 特性 | 单元测试 | 基准测试 |
|------|---------|---------|
| 目的 | 验证正确性 | 测量性能 |
| 关注点 | 结果对不对 | 运行快不快 |
| 断言 | `assert_eq!` | 执行时间/迭代次数 |
| 运行频率 | 每次提交 | 性能优化时 |

### 性能问题示例

```rust
// 两个功能相同但性能不同的实现

// 实现 1：使用 push
fn build_string_v1(n: usize) -> String {
    let mut s = String::new();
    for i in 0..n {
        s.push_str(&format!("{}", i));
    }
    s
}

// 实现 2：预分配容量
fn build_string_v2(n: usize) -> String {
    let mut s = String::with_capacity(n * 3);  // 预估每个数字约 3 字符
    for i in 0..n {
        s.push_str(&format!("{}", i));
    }
    s
}

// 哪个更快？快多少？需要基准测试！
```

## Criterion：Rust 基准测试框架

### 安装 Criterion

在 `Cargo.toml` 中添加：

```toml
[dev-dependencies]
criterion = "0.5"

[[bench]]
name = "my_benchmark"
harness = false
```

### 基本使用

创建 `benches/my_benchmark.rs`：

```rust
use criterion::{black_box, criterion_group, criterion_main, Criterion};

fn build_string_v1(n: usize) -> String {
    let mut s = String::new();
    for i in 0..n {
        s.push_str(&format!("{}", i));
    }
    s
}

fn build_string_v2(n: usize) -> String {
    let mut s = String::with_capacity(n * 3);
    for i in 0..n {
        s.push_str(&format!("{}", i));
    }
    s
}

fn benchmark_build_string(c: &mut Criterion) {
    let mut group = c.benchmark_group("Build String");
    
    group.bench_function("v1_no_capacity", |b| {
        b.iter(|| build_string_v1(black_box(1000)))
    });
    
    group.bench_function("v2_with_capacity", |b| {
        b.iter(|| build_string_v2(black_box(1000)))
    });
    
    group.finish();
}

criterion_group!(benches, benchmark_build_string);
criterion_main!(benches);
```

### 运行基准测试

```bash
# 运行所有基准测试
cargo bench

# 运行特定基准测试
cargo bench --bench my_benchmark

# 过滤特定测试
cargo bench -- "Build String"
```

### 解读结果

```
running 2 tests
Build String/v1_no_capacity
                        time:   [2.3456 ms 2.3891 ms 2.4321 ms]
                        change: [+5.2345% +6.1234% +7.0123%] (p = 0.00 < 0.05)
                        Performance has regressed.
Build String/v2_with_capacity
                        time:   [1.2345 ms 1.2567 ms 1.2789 ms]
                        change: [-2.3456% -1.8901% -1.4567%] (p = 0.00 < 0.05)
                        Performance has improved.
```

**结果解读：**
- `time`: 执行时间（最小值 - 平均值 - 最大值）
- `change`: 与上次运行的对比
- `p value`: 统计显著性（< 0.05 表示变化显著）

## Criterion 进阶用法

### 1. 参数化基准测试

```rust
use criterion::{BenchmarkId, Criterion};

fn fibonacci(n: u64) -> u64 {
    match n {
        0 => 0,
        1 => 1,
        _ => fibonacci(n - 1) + fibonacci(n - 2),
    }
}

fn fibonacci_iterative(n: u64) -> u64 {
    let mut a = 0;
    let mut b = 1;
    for _ in 0..n {
        let temp = a;
        a = b;
        b = temp + b;
    }
    a
}

fn benchmark_fibonacci(c: &mut Criterion) {
    let mut group = c.benchmark_group("Fibonacci");
    
    for i in [10, 20, 30].iter() {
        group.bench_with_input(
            BenchmarkId::new("recursive", i),
            i,
            |b, &i| b.iter(|| fibonacci(i)),
        );
        
        group.bench_with_input(
            BenchmarkId::new("iterative", i),
            i,
            |b, &i| b.iter(|| fibonacci_iterative(i)),
        );
    }
    
    group.finish();
}
```

### 2. 比较多种实现

```rust
fn sum_vec_v1(vec: &[i32]) -> i32 {
    let mut sum = 0;
    for &x in vec {
        sum += x;
    }
    sum
}

fn sum_vec_v2(vec: &[i32]) -> i32 {
    vec.iter().sum()
}

fn sum_vec_v3(vec: &[i32]) -> i32 {
    vec.par_iter().sum()  // 需要 rayon
}

fn benchmark_sum(c: &mut Criterion) {
    let vec: Vec<i32> = (0..10000).collect();
    
    let mut group = c.benchmark_group("Sum Vector");
    group.throughput(criterion::Throughput::Elements(vec.len() as u64));
    
    group.bench_function("for_loop", |b| b.iter(|| sum_vec_v1(black_box(&vec))));
    group.bench_function("iter_sum", |b| b.iter(|| sum_vec_v2(black_box(&vec))));
    group.bench_function("parallel", |b| b.iter(|| sum_vec_v3(black_box(&vec))));
    
    group.finish();
}
```

```rust
use criterion::{Bencher, BenchmarkId, Criterion, Throughput};

fn benchmark_with_setup(c: &mut Criterion) {
    let mut group = c.benchmark_group("Database Query");
    
    group.setup(|_| {
        // 设置代码，每个基准测试前运行
        println!("Setting up database connection...");
    });
    
    group.bench_function(BenchmarkId::from_parameter("query"), |b| {
        b.iter_custom(|iters| {
            let start = std::time::Instant::now();
            for _ in 0..iters {
                // 被测量的代码
                std::hint::black_box(42);
            }
            start.elapsed()
        })
    });
    
    group.finish();
}
```

## 常见性能优化技巧

### 1. 预分配容量

```rust
// ❌ 慢：多次重新分配
let mut vec = Vec::new();
for i in 0..1000 {
    vec.push(i);
}

// ✅ 快：预分配容量
let mut vec = Vec::with_capacity(1000);
for i in 0..1000 {
    vec.push(i);
}
```

### 2. 使用迭代器而非索引

```rust
// ❌ 慢：边界检查
let mut sum = 0;
for i in 0..vec.len() {
    sum += vec[i];
}

// ✅ 快：迭代器优化
let sum: i32 = vec.iter().sum();
```

### 3. 避免不必要的克隆

```rust
// ❌ 慢：不必要的克隆
fn process(data: Vec<String>) -> Vec<String> {
    data.iter().map(|s| s.clone().to_uppercase()).collect()
}

// ✅ 快：借用
fn process(data: &[String]) -> Vec<String> {
    data.iter().map(|s| s.to_uppercase()).collect()
}
```

### 4. 使用合适的数据结构

```rust
// 查找操作
// Vec: O(n)  - 适合小数据集
// HashMap: O(1) - 适合大数据集频繁查找
// BTreeMap: O(log n) - 需要有序

// 成员检查
// Vec: O(n)
// HashSet: O(1)
```

### 5. 并行处理

```rust
use rayon::prelude::*;

// 串行
let sum: i32 = vec.iter().sum();

// 并行（适合大数据集）
let sum: i32 = vec.par_iter().sum();
```

## 实战：优化字符串处理

### 初始实现

```rust
fn process_text(text: &str) -> String {
    let mut result = String::new();
    
    for line in text.lines() {
        let trimmed = line.trim();
        if !trimmed.is_empty() {
            let upper = trimmed.to_uppercase();
            result.push_str(&upper);
            result.push('\n');
        }
    }
    
    result
}
```

### 基准测试

```rust
fn benchmark_process_text(c: &mut Criterion) {
    let text = "Hello\nWorld\n\nRust\n\nProgramming\n";
    
    c.bench_function("process_text_v1", |b| {
        b.iter(|| process_text(black_box(text)))
    });
}
```

### 优化版本 1：预分配

```rust
fn process_text_v2(text: &str) -> String {
    let mut result = String::with_capacity(text.len());
    
    for line in text.lines() {
        let trimmed = line.trim();
        if !trimmed.is_empty() {
            let upper = trimmed.to_uppercase();
            result.push_str(&upper);
            result.push('\n');
        }
    }
    
    result
}
```

### 优化版本 2：使用迭代器

```rust
fn process_text_v3(text: &str) -> String {
    text.lines()
        .map(|line| line.trim())
        .filter(|line| !line.is_empty())
        .map(|line| line.to_uppercase())
        .collect::<Vec<_>>()
        .join("\n")
}
```

### 优化版本 3：避免中间集合

```rust
fn process_text_v4(text: &str) -> String {
    let mut result = String::with_capacity(text.len());
    
    for line in text.lines() {
        let trimmed = line.trim();
        if !trimmed.is_empty() {
            for c in trimmed.chars() {
                result.push(c.to_ascii_uppercase());
            }
            result.push('\n');
        }
    }
    
    result
}
```

### 基准测试对比

```rust
fn benchmark_all_versions(c: &mut Criterion) {
    let text = "Hello\nWorld\n\nRust\n\nProgramming\n".repeat(100);
    
    let mut group = c.benchmark_group("Process Text");
    group.throughput(criterion::Throughput::Bytes(text.len() as u64));
    
    group.bench_function("v1_original", |b| {
        b.iter(|| process_text(black_box(&text)))
    });
    
    group.bench_function("v2_with_capacity", |b| {
        b.iter(|| process_text_v2(black_box(&text)))
    });
    
    group.bench_function("v3_iterator", |b| {
        b.iter(|| process_text_v3(black_box(&text)))
    });
    
    group.bench_function("v4_optimized", |b| {
        b.iter(|| process_text_v4(black_box(&text)))
    });
    
    group.finish();
}
```

### 预期结果

```

Process Text/v2_with_capacity time: [12.345 ms 12.567 ms 12.789 ms]  # 提升 20%
Process Text/v3_iterator      time: [14.123 ms 14.345 ms 14.567 ms]  # 提升 8%
```

## 关键概念理解

### 1. black_box 的作用

```rust
use std::hint::black_box;

// 防止编译器优化掉被测量的代码
fn benchmark(b: &mut Bencher) {
    b.iter(|| {
        // 没有 black_box，编译器可能优化掉这个计算
        let result = expensive_computation(42);
        black_box(result);  // 告诉编译器：这个结果会被使用
    });
}
```

### 2. 统计显著性

Criterion 使用统计方法确保结果可靠：

- **多次采样**：每个测试运行多次
- **置信区间**：95% 置信度
- **异常值检测**：自动识别并处理异常值
- **p 值**：判断变化是否显著（< 0.05）

### 3. 吞吐量 vs 时间

```rust
// 按时间测量
group.bench_function("sort", |b| b.iter(|| sort(&data)));

// 按吞吐量测量（适合处理大量数据）
group.throughput(Throughput::Bytes(data.len() as u64));
group.bench_function("process", |b| b.iter(|| process(&data)));
```

### 4. 热身（Warm-up）

```rust
let mut group = c.benchmark_group("My Benchmark");
group.warm_up_time(Duration::from_secs(3));  // 热身 3 秒
group.measurement_time(Duration::from_secs(10));  // 测量 10 秒
```

## 练习题

### 练习 1：基准测试两种排序算法

```rust
fn bubble_sort(mut vec: Vec<i32>) -> Vec<i32> {
    let len = vec.len();
    for i in 0..len {
        for j in 0..len - i - 1 {
            if vec[j] > vec[j + 1] {
                vec.swap(j, j + 1);
            }
        }
    }
    vec
}

fn quick_sort(mut vec: Vec<i32>) -> Vec<i32> {
    if vec.len() <= 1 {
        return vec;
    }
    
    let pivot = vec.pop().unwrap();
    let (less, greater): (Vec<_>, Vec<_>) = vec
        .into_iter()
        .partition(|&x| x <= pivot);
    
    let mut result = quick_sort(less);
    result.push(pivot);
    result.extend(quick_sort(greater));
    result
}
```

- 使用 Criterion 比较两种算法
- 测试不同大小的输入（100, 1000, 10000 元素）

## 今日感悟

今天的性能测试学习让我有了几个重要认识：

1. **测量优于猜测** - 以前总觉得"这段代码应该很快"，但基准测试告诉我，直觉常常是错的。只有测量才能知道真相。

2. **微优化的陷阱** - 有些优化看起来"应该"更快，但实际提升微乎其微。基准测试帮助我把精力放在真正有影响的地方。

3. **Criterion 的强大** - 统计显著性、自动重试、可视化报告... 这些功能让性能测试变得科学可靠，不再是"跑一次看时间"。

4. **预分配的力量** - 今天最惊喜的发现是 `with_capacity` 的优化效果。在很多场景下，简单的预分配能带来 20-30% 的提升。

5. **并行不是银弹** - 对于小数据集，并行反而更慢（线程开销）。基准测试帮助找到并行的临界点。

6. **性能是功能的一部分** - 正确的代码但太慢，对用户来说就是"错误的代码"。性能测试应该和单元测试一样重要。

7. **持续监控** - 性能回归检测让我意识到，性能不应该只在发布前检查，而应该持续监控。

明天的周总结将把本周所有测试知识串联起来。期待形成完整的测试方法论！
