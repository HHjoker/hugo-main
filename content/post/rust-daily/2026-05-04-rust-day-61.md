## 为什么需要异步编程？

在深入语法之前，先理解**为什么**需要异步。考虑一个典型的 Web 服务器场景：

```rust
// ❌ 同步方式：每次请求都会阻塞一个线程
fn handle_request(url: &str) -> String {
    let response = reqwest::blocking::get(url).unwrap(); // 阻塞等待！
    response
}
```

如果 1000 个并发请求到来，同步方式需要 1000 个线程，内存和 CPU 开销巨大。

```rust
// ✅ 异步方式：单个线程即可处理大量并发
async fn handle_request(url: &str) -> String {
    reqwest::get(url).await.unwrap().text().await.unwrap()
}
```

**异步的核心思想**：当任务等待 I/O 时，不阻塞线程，转而执行其他任务。线程只在有实际 CPU 工作时才被占用。

## 一、async fn：定义异步函数

### 基本语法

```rust
// 普通函数：同步执行，调用会阻塞
fn sync_function() -> String {
    String::from("同步结果")
}

// 异步函数：返回 Future，不立即执行
async fn async_function() -> String {
    String::from("异步结果")
}
```

关键点：`async fn` 的函数体**并不自动在后台运行**。调用它只会创建一个 `Future`，必须通过 `.await` 或 executor 来驱动它执行。

### async fn 的返回值

```rust
// async fn 的返回类型自动推断为 impl Future<Output = T>
async fn fetch_data() -> impl Future<Output = String> {
    // 这里可以写任意的异步代码
    String::from("数据加载完成").into()
}
```

实际上，你不需要手动写 `impl Future`，编译器会自动推断：

```rust
// 编译器会生成等价的 Future 类型
async fn greet() -> String {
    String::from("Hello, Rust!")
}

// 使用方式
fn main() {
    let future = greet(); // 创建一个 Future，还未执行
    // 需要 executor 来运行这个 Future
}
```

## 二、.await：等待异步操作

`.await` 是异步代码中的**核心操作符**，它的作用是：

> "暂停当前 Future 的执行，等待另一个 Future 完成后继续。"

### 对比：同步 vs 异步

```rust
// ============ 同步版本 ============
fn main() {
    let result = blocking_task(); // 程序在这里卡住，什么也做不了
    println!("{}", result);
}

fn blocking_task() -> String {
    std::thread::sleep(std::time::Duration::from_secs(2));
    String::from("完成")
}
```

```rust
// ============ 异步版本（需要运行时） ============
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    // sleep 是一个 async fn，返回 Future
    // .await 不会阻塞线程，而是让出给其他任务
    sleep(Duration::from_secs(2)).await;
    println!("2秒后打印这条消息");
}
```

`.await` 的重要特性：

1. **不阻塞线程**：等待期间，线程可以去执行其他 Future
2. **只能用在 async 上下文中**：`.await` 必须位于 `async fn` 或另一个 Future 的上下文中
3. **立即返回**（表面上看）：调用 `.await` 的代码会"暂停"，直到 Future 完成

## 三、第一个完整的异步程序：使用 Tokio

Tokio 是 Rust 最流行的异步运行时。让我们写一个真实可运行的例子：

```rust
// Cargo.toml 添加依赖：
// tokio = { version = "1", features = ["full"] }

use tokio::time::{sleep, Duration};

#[tokio::main]  // 异步入口点，自动创建并运行 Tokio 运行时
async fn main() {
    println!("程序开始: {}", chrono::Local::now().format("%H:%M:%S"));

    // 并发执行两个异步任务
    let task1 = download_file("document.pdf");
    let task2 = process_image("avatar.png");

    // 使用 join! 并发等待两个任务
    let (result1, result2) = tokio::join!(task1, task2);

    println!("文件下载: {}", result1);
    println!("图片处理: {}", result2);
    println!("程序结束: {}", chrono::Local::now().format("%H:%M:%S"));
}

async fn download_file(filename: &str) -> String {
    sleep(Duration::from_secs(2)).await;
    format!("已下载: {}", filename)
}

async fn process_image(filename: &str) -> String {
    sleep(Duration::from_secs(3)).await;
    format!("已处理: {}", filename)
}
```

**运行结果（注意总时长 ~3 秒，不是 5 秒）：**

```
程序开始: 13:00:00
文件下载: 已下载: document.pdf
图片处理: 已处理: avatar.png
程序结束: 13:00:03
```

`tokio::join!` 让两个任务**同时执行**，总耗时等于最长任务的耗时，而非所有任务耗时之和。

## 四、async 与并发、并行

这是两个容易混淆的概念：

```
并发 (Concurrency)：同时**管理**多个任务，但不一定同时**执行**
并行 (Parallelism) ：同时**执行**多个任务
```

Rust 异步属于**并发**模型：

```rust
// 这个例子展示了异步并发（非并行）
#[tokio::main]
async fn main() {
    // 100 个爬虫任务同时"进行"，但都在同一个线程上
    let mut handles = vec![];
    
    for i in 0..100 {
        let handle = tokio::spawn(async move {
            fetch_url(&format!("https://api.example.com/item/{}", i)).await
        });
        handles.push(handle);
    }
    
    // 等待所有任务完成
    let results = futures::future::join_all(handles).await;
    println!("完成了 {} 个请求", results.len());
}

async fn fetch_url(url: &str) -> String {
    // 模拟网络请求
    tokio::time::sleep(std::time::Duration::from_millis(100)).await;
    url.to_string()
}
```

在多核机器上，Tokio 会自动将多个任务**并行**分配到不同线程，但这种并行对代码是透明的——你不需要手动管理线程。

## 五、tokio::spawn：跨任务调度

`tokio::spawn` 用于**创建新任务**（task），这些任务会被 Tokio 运行时自动调度到线程池：

```rust
#[tokio::main]
async fn main() {
    // spawn 返回 JoinHandle，可以用来获取任务结果
    let handle = tokio::spawn(async {
        // 这个代码块运行在后台任务中
        calculate_prime(10000).await
    });

    // 主任务可以同时做其他事情
    let result = tokio::time::timeout(
        std::time::Duration::from_secs(5),
        async {
            loop {
                println!("主任务正在运行... ");
                tokio::time::sleep(std::time::Duration::from_secs(1)).await;
            }
        }
    ).await;

    // 等待 spawn 的任务结果
    let prime_count = handle.await.unwrap();
    println!("找到 {} 个质数", prime_count);
}

async fn calculate_prime(max: u64) -> u64 {
    (2..=max).filter(|n| is_prime(*n)).count() as u64
}

fn is_prime(n: u64) -> bool {
    if n < 2 { return false; }
    for i in 2..=(n as f64).sqrt() as u64 {
        if n % i == 0 { return false; }
    }
    true
}
```

`tokio::spawn` 的特点：
- 返回 `JoinHandle<T>`，可用于获取任务返回值或检查是否成功完成
- 任务在后台运行，不会阻塞调用者
- 任务拥有独立的任务上下文（task context），可以在其中使用 `.await`

## 六、async 代码中的错误处理

异步代码的错误处理与同步代码类似，使用 `Result`：

```rust
use tokio::fs::File;
use tokio::io::{AsyncReadExt, AsyncWriteExt};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // ============ 异步文件读取 ============
    let mut file = File::open("data.txt").await?;
    
    let mut contents = String::new();
    file.read_to_string(&mut contents).await?;
    println!("文件内容: {}", contents);

    // ============ 异步文件写入 ============
    let mut file = File::create("output.txt").await?;
    file.write_all(b"Hello, async Rust!").await?;
    
    println!("写入完成");
    Ok(())
}
```

关键：`?` 运算符在 async fn 中同样工作，可以直接传播错误。

## 七、async 生命周期注意事项

`async fn` 中的生命周期有一些特殊规则：

```rust
// ✅ 正确：'a 在整个 async 块期间有效
async fn longest<'a>(s1: &'a str, s2: &'a str) -> &'a str {
    if s1.len() > s2.len() { s1 } else { s2 }
}

// ⚠️ 错误示例：返回引用但 'a 生命周期不明确
// async fn bad_example(s: &str) -> &str {  // 编译错误！
//     s
// }

// ✅ 正确做法：使用带有生命周期的 async fn
async fn good_example<'a>(s: &'a str) -> &'a str {
    s
}
```

异步上下文中引用和生命周期的交互比同步代码更复杂，因为 Future 可能被 `.await` 多次暂停，引用必须确保在整个 Future 生命周期内有效。

## 关键概念理解

### 1. Future 是什么？

`Future` 是 Rust 异步的核心抽象，代表一个**异步计算**：

```rust
pub trait Future {
    type Output;  // Future 最终产生的值
    
    // poll 方法由 executor 调用
    // Poll::Ready(v) 表示完成，返回值 v
    // Poll::Pending 表示还没好，需要继续等待
    fn poll(self: Pin<&mut Self>, cx: &mut Context)
        -> Poll<Self::Output>;
}
```

`Pin` 和 `Context` 是 `poll` 的额外参数，确保自引用结构的安全性和任务唤醒机制的实现。

### 2. async vs thread：什么时候选哪个？

| 场景 | 推荐方式 |
|------|---------|
| 高并发 I/O（HTTP、数据库、文件） | async + Tokio |
| CPU 密集型计算 | 多线程（`std::thread` 或 `rayon`）|
| 简单并发，且不需要极致性能 | 都可以，看团队熟悉度 |
| 需要调用阻塞的 C 库 | `spawn_blocking` 或切换到同步线程 |

**黄金法则**：
- I/O 密集型 → 异步（数千并发连接，单线程即可）
- CPU 密集型 → 多线程（利用多核，并行计算）

### 3. #[tokio::main] 做了什么？

```rust
#[tokio::main]  // 这不是语法糖，是真正的宏展开
```

展开后大约等价于：

```rust
fn main() {
    let rt = tokio::runtime::Runtime::new().unwrap();
    rt.block_on(async {
        // 你的 main 函数代码在这里
    });
}
```

它创建了一个 Tokio 运行时，并在其中运行你的 `async fn main()`。

### 练习 2：并发下载模拟

使用 `tokio::join!` 同时执行三个"下载任务"，每个耗时不同，总耗时应该是最长的那个：

```rust
async fn download_a() { /* 耗时 1 秒 */ }
async fn download_b() { /* 耗时 2 秒 */ }
async fn download_c() { /* 耗时 3 秒 */ }

#[tokio::main]
async fn main() {
    let start = std::time::Instant::now();
    // 在这里使用 tokio::join! 并发执行三个下载
    // 总耗时应该约 3 秒，而非 6 秒
    let elapsed = start.elapsed();
    println!("总耗时: {:?}", elapsed);
    assert!(elapsed.as_secs() < 4, "应该并发执行！");
}
```

<details>
<summary>参考答案</summary>

```rust
#[tokio::main]
async fn main() {
    let start = std::time::Instant::now();
    tokio::join!(download_a(), download_b(), download_c());
    let elapsed = start.elapsed();
    println!("总耗时: {:?}", elapsed);
    assert!(elapsed.as_secs() < 4, "应该并发执行！");
}
```

</details>

### 练习 3：超时控制

使用 `tokio::time::timeout` 为一个会运行很久的任务添加超时：

```rust
async fn long_running_task() {
    tokio::time::sleep(std::time::Duration::from_secs(10)).await;
}

#[tokio::main]
async fn main() {
    // 使用 timeout 让任务最多运行 1 秒
    let result = tokio::time::timeout(
        std::time::Duration::from_secs(1),
        long_running_task()
    ).await;

    match result {
        Ok(_) => println!("任务正常完成"),
        Err(_) => println!("任务超时被取消！"),
    }
}
```

改写下面的同步文件读取为异步版本，处理可能出现的错误：

```rust
// 目标：异步读取文件并返回行数，如果文件不存在返回错误
async fn count_lines(filename: &str) -> Result<usize, Box<dyn std::error::Error>> {
    // 使用 tokio::fs::File 和 AsyncReadExt
    unimplemented!()
}
```

<details>
<summary>参考答案</summary>

```rust
use tokio::fs::File;
use tokio::io::{AsyncBufReadExt, BufReader};

async fn count_lines(filename: &str) -> Result<usize, Box<dyn std::error::Error>> {
    let file = File::open(filename).await?;
    let reader = BufReader::new(file);
    let mut lines = reader.lines();
    let mut count = 0;
    while lines.next_line().await? != None {
        count += 1;
    }
    Ok(count)
}
```

</details>

### 练习 5：使用 spawn 实现任务超时取消

用 `tokio::spawn` 和 `tokio::time::timeout` 实现：当任务超时，主动取消它：

```rust
async fn cancellable_task() {
    for i in 0..10 {
        println!("工作中... {}", i);
        tokio::time::sleep(std::time::Duration::from_secs(1)).await;
    }
    println!("任务完成！");
}

#[tokio::main]
async fn main() {
    // 使用 timeout 和 spawn 实现：任务最多运行 3 秒
    // 超时后任务应被取消，不再打印后续的 "工作中..."
}
```

<details>
<summary>参考答案</summary>

```rust
#[tokio::main]
async fn main() {
    let handle = tokio::spawn(cancellable_task());
    
    let result = tokio::time::timeout(
        std::time::Duration::from_secs(3),
        handle
    ).await;
    
    match result {
        Ok(Ok(_)) => println!("任务自己正常结束了"),
        Ok(Err(_)) => println!("任务 panicked"),
        Err(_) => println!("超时，任务被取消"),
    }
}
```

</details>
