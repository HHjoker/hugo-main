## 回顾：执行器与 Tokio

昨天我们手写了一个简化执行器，理解了 Future 的 poll 机制、Waker 唤醒和 Pin 的作用。

**真实世界的执行器**要比我们写的复杂得多。Tokio 是 Rust 生态中最成熟的生产级异步运行时。今天我们就深入了解 Tokio 的架构。

## 一、Tokio 简介

### 什么是 Tokio？

Tokio 是一个**异步运行时**，提供：
- 多线程任务调度器
- 异步 I/O（TCP/UDP/Unix socket）
- 定时器（sleep、timeout）
- 文件系统操作（异步）
- 同步原语（Mutex、channel 等）

### Tokio vs 其他选择

| 运行时 | 特点 |
|--------|------|
| **Tokio** | 最流行、生态丰富、生产级稳定 |
| **async-std** | 设计风格接近标准库，概念清晰 |
| **smol** | 轻量级、易于理解 |
| **glommio** | Linux io_uring 支持，高性能 |

Tokio 是目前最主流的选择，大多数生产项目都用它。

### 在 Cargo.toml 中添加 Tokio

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }

# 或者按需选择特性
tokio = { version = "1", features = [
    "rt-multi-thread",  # 多线程运行时
    "macros",           # #[tokio::main] 宏
    "sync",             # 同步工具（Mutex 等）
    "time",             # 时间相关功能
    "net",              # 网络功能
] }
```

## 二、Tokio 运行模式

Tokio 有两种运行模式：

### 1. 单线程模式（current_thread）

只在一个线程上运行 Future，适合简单场景：

```rust
use tokio::runtime::Builder;

fn main() {
    // 创建单线程运行时
    let runtime = Builder::new_current_thread()
        .build()
        .unwrap();

    // 在这个线程上运行 Future
    runtime.block_on(async {
        println!("在单线程运行时中运行");
        tokio::time::sleep(std::time::Duration::from_millis(10)).await;
        println!("完成！");
    });
}
```

### 2. 多线程模式（multi-thread）

默认模式，在多个线程上并行运行任务：

```rust
use tokio;

#[tokio::main]  // 这是 #[tokio::main] 宏的展开
async fn main() {
    println!("在多线程运行时中运行");
    
    // spawn 会把任务分配到线程池
    let handle = tokio::spawn(async {
        tokio::time::sleep(std::time::Duration::from_millis(10)).await;
        "任务完成"
    });

    // 等待任务完成
    let result = handle.await.unwrap();
    println!("结果: {}", result);
}
```

### #[tokio::main] 宏展开

`#[tokio::main]` 实际上做了这些事情：

```rust
// 你写的代码：
#[tokio::main]
async fn main() {
    // ...
}

// 展开后大概是：
fn main() {
    let runtime = tokio::runtime::Builder::new_multi_thread()
        .worker_threads(4)  // 默认4个工作线程
        .enable_all()
        .build()
        .unwrap();
    
    runtime.block_on(async {
        // 你写的 main 函数作为 async block
        // ...
    });
}
```

### 自定义运行时配置

```rust
use tokio::runtime::{Builder, Runtime};

fn create_runtime() -> Runtime {
    Builder::new_multi_thread()
        .worker_threads(8)          // 8 个工作线程（默认 CPU 核数）
        .thread_name("my-tokio-worker")
        .thread_stack_size(2 * 1024 * 1024)  // 线程栈大小
        .enable_time()
        .enable_io()
        .build()
        .unwrap()
}

fn main() {
    let runtime = create_runtime();
    
    runtime.block_on(async {
        // 任务
    });
}
```

## 三、spawn 与任务调度

### 基本 spawn 用法

`tokio::spawn` 将一个 Future 发送到线程池中执行：

```rust
use tokio;

#[tokio::main]
async fn main() {
    // spawn 返回 JoinHandle，可以等待任务完成
    let handle = tokio::spawn(async {
        // 这个 async 块会在某个工作线程上执行
        tokio::time::sleep(std::time::Duration::from_millis(100)).await;
        42
    });

    // 在主任务中做其他事
    println!("等待 spawn 的任务...");

    // 等待并获取结果
    let result = handle.await.unwrap();
    println!("spawn 任务返回: {}", result);
}
```

### spawn 是非阻塞的

注意：`spawn` 本身是立即返回的，不会等待 Future 完成：

```rust
#[tokio::main]
async fn main() {
    println!("spawn 之前");

    let handle = tokio::spawn(async {
        println!("spawn 的任务开始");
        tokio::time::sleep(std::time::Duration::from_millis(10)).await;
        println!("spawn 的任务结束");
        "done"
    });

    println!("spawn 之后（任务还在运行）");

    // handle.await 会阻塞当前任务，等待 spawn 的任务完成
    let _ = handle.await;

    println!("spawn 的任务已结束");
}
```

输出：
```
spawn 之前
spawn 之后（任务还在运行）
spawn 的任务开始
spawn 的任务结束
spawn 的任务已结束
```

### 多任务 spawn

```rust
#[tokio::main]
async fn main() {
    let mut handles = vec![];

    for i in 0..5 {
        let handle = tokio::spawn(async move {
            tokio::time::sleep(std::time::Duration::from_millis(10 * i as u64)).await;
            format!("任务 {} 完成", i)
        });
        handles.push(handle);
    }

    // 等待所有任务
    for handle in handles {
        let result = handle.await.unwrap();
        println!("{}", result);
    }
}
```

## 四、工作线程池的调度机制

### Tokio 的调度模型

```
                    ┌─────────────────────────────────────┐
                    │            Tokio Runtime             │
                    │                                      │
  spawn(Future) ──→ │   ┌──────────────────────────────┐  │
                    │   │        Task Queue             │  │
                    │   │  (每个 Worker Thread 一个)     │  │
                    │   └──────────────────────────────┘  │
                    │              ↓  ↓  ↓                │
                    │   ┌────────┐ ┌────────┐ ┌────────┐  │
                    │   │Worker 1│ │Worker 2│ │Worker 3│  │
                    │   └────────┘ └────────┘ └────────┘  │
                    │   (poll Future)  (poll Future)      │
                    └─────────────────────────────────────┘

每个 Worker Thread：
1. 从自己的本地队列取任务
2. poll 任务（调用 Future.poll）
3. 如果 Future 返回 Pending，任务留在队列
4. 如果 Future 完成，任务从队列移除
```

### steal（任务窃取）

如果某个工作线程的队列空了，它会从其他线程的队列"窃取"任务：

```rust
// Tokio 的调度策略：
// 1. 优先从本地队列取任务
// 2. 本地队列空时，从其他线程窃取
// 3. 窃取时随机选择目标队列

// 这保证了：
// - 任务尽量在创建它的线程上执行（缓存友好）
// - 负载均衡（没有线程空闲而其他线程忙）
```

### 设置工作线程数

```rust
use tokio::runtime::Builder;

fn main() {
    // 方式 1：环境变量
    // RAYON_NUM_THREADS=8 cargo run

    // 方式 2：代码配置
    let runtime = Builder::new_multi_thread()
        .worker_threads(8)  // 8 个工作线程
        .build()
        .unwrap();

    runtime.block_on(async {
        // ...
    });
}

// 方式 3：使用 #[tokio::main(flavor = "multi_thread")]
#[tokio::main(flavor = "multi_thread", worker_threads = 8)]
async fn main() {
    // ...
}
```

## 五、spawn_blocking：处理阻塞代码

### 为什么要用 spawn_blocking？

有些操作是**阻塞的**（CPU密集计算、调用同步库等），不应该在异步线程上执行：

```
⚠️ 问题场景：
┌────────────────────────────────────────┐
│  假设你在异步线程中执行 CPU 密集计算：   │
│                                        │
│  tokio::spawn(async {                  │
│      let result = cpu_heavy_task();    │ ← 这个线程被阻塞
│      result                             │   其他任务无法使用
│  });                                    │   这个线程
└────────────────────────────────────────┘

解决方案：用 spawn_blocking 移到专用线程：
┌────────────────────────────────────────┐
│  tokio::spawn_blocking(|| {            │
│      // 在专用线程执行，不阻塞异步线程   │
│      cpu_heavy_task()                  │
│  });                                   │
└────────────────────────────────────────┘
```

### spawn_blocking 基本用法

```rust
use tokio;

#[tokio::main]
async fn main() {
    // 使用 spawn_blocking 处理阻塞操作
    let result = tokio::task::spawn_blocking(|| {
        // 这个闭包会在一个专门的"阻塞线程"上执行
        println!("在阻塞线程中执行...");
        
        // 模拟 CPU 密集计算
        let sum: u64 = (1..=1000000).sum();
        
        std::thread::sleep(std::time::Duration::from_millis(100));
        
        sum
    }).await.unwrap();

    println!("spawn_blocking 结果: {}", result);
}
```

### spawn vs spawn_blocking 对比

| 场景 | 使用 spawn | 使用 spawn_blocking |
|------|------------|---------------------|
| 异步 I/O（HTTP请求、数据库查询） | ✅ | ❌ |
| CPU 密集计算 | ❌ | ✅ |
| 调用同步阻塞库 | ❌ | ✅ |
| 并行处理独立任务 | ✅ | ❌ |

### spawn_blocking 的线程池

Tokio 维护一个单独的**阻塞线程池**：

```rust
use tokio::runtime::Builder;

fn main() {
    let runtime = Builder::new_multi_thread()
        .worker_threads(4)           // 异步工作线程数
        .max_blocking_threads(16)    // 阻塞线程数上限（默认 512）
        .build()
        .unwrap();
    
    runtime.block_on(async {
        // spawn_blocking 会使用阻塞线程池
        let _ = tokio::task::spawn_blocking(|| {
            // 阻塞操作
        }).await;
    });
}
```

### 实际示例：文件 I/O

```rust
use tokio;
use tokio::fs;

#[tokio::main]
async fn main() -> std::io::Result<()> {
    // Tokio 的 fs 模块是异步的，但底层也是通过 spawn_blocking 实现
    let contents = fs::read_to_string("data.txt").await?;
    
    println!("文件内容: {}", contents);
    
    // 对于完全同步的代码，自己用 spawn_blocking
    let hash = tokio::task::spawn_blocking(|| {
        // 假设有个同步的哈希计算
        compute_hash_sync()
    }).await.unwrap();
    
    println!("哈希值: {}", hash);
    
    Ok(())
}

fn compute_hash_sync() -> String {
    // 模拟同步计算
    std::thread::sleep(std::time::Duration::from_millis(50));
    "abc123".to_string()
}
```

## 六、LocalSet：线程本地任务组

### 什么是 LocalSet？

有时候你希望某些任务**只在当前线程**执行，不分配到全局线程池：

```rust
use tokio;

fn main() {
    // 创建只属于当前线程的任务集合
    let local_set = tokio::task::LocalSet::new();

    // 在这个 LocalSet 中运行任务
    local_set.block_on(async {
        // 这个任务只会在当前线程执行
        let handle = tokio::spawn(async {
            42
        });

        let result = handle.await.unwrap();
        println!("结果: {}", result);
    });
}
```

### LocalSet 使用场景

```rust
use tokio::task::LocalSet;

fn main() {
    let local_set = LocalSet::new();

    // 可以 spawn 多个本地任务
    local_set.block_on(async {
        let a = tokio::spawn(async { 1 });
        let b = tokio::spawn(async { 2 });
        
        assert_eq!(a.await.unwrap() + b.await.unwrap(), 3);
    });
}
```

### 与 spawn_blocking 的配合

```rust
use tokio::task::{LocalSet, spawn_local};

fn main() {
    let local_set = LocalSet::new();

    local_set.block_on(async {
        // spawn_local 创建的任务只在当前线程运行
        let handle = spawn_local(async {
            tokio::time::sleep(std::time::Duration::from_millis(10)).await;
            "本地任务完成"
        });

        let result = handle.await.unwrap();
        println!("{}", result);
    });
}
```

## 七、Runtime 嵌套

### 在已有运行时中启动新运行时

```rust
use tokio::runtime::Builder;

fn main() {
    let outer_runtime = Builder::new_multi_thread()
        .thread_name("outer")
        .build()
        .unwrap();

    outer_runtime.block_on(async {
        println!("在外层运行时中");

        // ⚠️ 在异步上下文中创建新运行时需要谨慎
        // 通常不推荐在已有运行时中创建新的 multi-thread 运行时
        
        // 更好的做法：创建 current_thread 运行时
        let inner_runtime = Builder::new_current_thread()
            .thread_name("inner")
            .build()
            .unwrap();

        inner_runtime.block_on(async {
            println!("在内层 current_thread 运行时中");
        });

        println!("回到外层运行时");
    });
}
```

### spawn 到不同的运行时

```rust
use tokio::runtime::Builder;
use std::thread;

fn main() {
    // 创建两个独立的运行时
    let runtime1 = Builder::new_multi_thread()
        .thread_name("runtime1")
        .build()
        .unwrap();
    
    let runtime2 = Builder::new_multi_thread()
        .thread_name("runtime2")
        .build()
        .unwrap();

    // runtime1 处理一些任务
    runtime1.block_on(async {
        let handle = tokio::spawn(async {
            tokio::time::sleep(std::time::Duration::from_millis(10)).await;
            "from runtime1"
        });
        let result = handle.await.unwrap();
        println!("{}", result);
    });

    runtime2.block_on(async {
        let handle = tokio::spawn(async {
            tokio::time::sleep(std::time::Duration::from_millis(10)).await;
            "from runtime2"
        });
        let result = handle.await.unwrap();
        println!("{}", result);
    });
}
```

## 八、任务取消与 Timeout

### 使用 AbortHandle 取消任务

```rust
use tokio;

#[tokio::main]
async fn main() {
    let handle = tokio::spawn(async {
        loop {
            println!("任务运行中...");
            tokio::time::sleep(std::time::Duration::from_millis(100)).await;
        }
    });

    // 3 秒后取消任务
    tokio::time::sleep(std::time::Duration::from_secs(3)).await;
    
    println!("开始取消任务...");
    handle.abort();
    
    // join 会返回错误，因为任务被取消了
    let result = handle.await;
    
    match result {
        Ok(_) => println!("任务正常完成"),
        Err(e) if e.is_cancelled() => println!("任务被取消"),
        Err(e) => println!("其他错误: {:?}", e),
    }
}
```

### 使用 join! 等待多个任务并处理取消

```rust
use tokio::{spawn, time::{sleep, Duration}};

#[tokio::main]
async fn main() {
    let long_task = spawn(async {
        loop {
            println!("长时间任务运行中");
            sleep(Duration::from_millis(100)).await;
        }
    });

    let timeout_task = spawn(async {
        sleep(Duration::from_secs(2)).await;
        println!("timeout 任务完成");
    });

    // 等待任意一个完成
    let mut handles = vec![long_task, timeout_task];
    
    while !handles.is_empty() {
        for i in 0..handles.len() {
            match handles[i].now_or_never() {
                Some(Ok(())) => {
                    println!("任务 {} 完成", i);
                }
                Some(Err(e)) => {
                    println!("任务 {} 出错: {:?}", i, e);
                }
                None => {}
            }
        }
        
        if handles.len() == 2 {
            // 两个都还没完成，继续等
            sleep(Duration::from_millis(10)).await;
        }
    }
}
```

### Timeout 包装器

```rust
use tokio::{time::{timeout, Duration}, fs};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // 超时包装：5 秒后自动取消
    let result = timeout(Duration::from_secs(5), async {
        // 模拟一个长时间操作
        fs::read_to_string("large_file.txt").await
    }).await;

    match result {
        Ok(contents) => println!("文件内容: {}", contents),
        Err(_) => println!("操作超时！"),
    }

    // 另一个例子：等待 spawn 的任务
    let handle = tokio::spawn(async {
        tokio::time::sleep(Duration::from_secs(10)).await;
        "done"
    });

    let result = timeout(Duration::from_secs(1), handle).await;
    
    match result {
        Ok(Ok(value)) => println!("任务完成: {}", value),
        Ok(Err(e)) => println!("任务错误: {:?}", e),
        Err(_) => println!("任务超时被取消"),
    }

    Ok(())
}
```

## 关键概念理解

### 1. Tokio 运行时的两种模式

```
┌─────────────────────────────────────────────────────┐
│                  Tokio 运行模式                      │
│                                                      │
│  current_thread          multi_thread                │
│  ┌────────────────┐       ┌────────────────────────┐ │
│  │  单个线程      │       │  多个工作线程           │ │
│  │  简单场景      │       │  高并发场景             │ │
│  │  无需调度开销  │       │  负载均衡               │ │
│  └────────────────┘       └────────────────────────┘ │
│                                                      │
│  适用：CLI 工具、单元测试、简单服务器                  │
│  适用：生产级服务器、高并发处理                        │
└─────────────────────────────────────────────────────┘
```

### 2. spawn vs spawn_blocking

```
┌──────────────────────────────────────────────────────────┐
│                    spawn vs spawn_blocking                │
│                                                          │
│  spawn (async)          spawn_blocking (sync)            │
│  ┌────────────────┐      ┌────────────────────────┐      │
│  │ 在异步线程池   │      │ 在专用阻塞线程池       │      │
│  │ 执行 async fn  │      │ 执行同步阻塞代码       │      │
│  │ 不阻塞线程     │      │ 可能阻塞线程           │      │
│  └────────────────┘      └────────────────────────┘      │
│                                                          │
│  场景：                          场景：                   │
│  - 网络请求                      - CPU 密集计算           │
│  - 数据库查询                    - 同步库调用             │
│  - 文件 I/O（异步）              - 长时间同步操作         │
└──────────────────────────────────────────────────────────┘
```

### 3. Tokio 线程池架构

```
┌─────────────────────────────────────────────────────────────┐
│                      Tokio Runtime                          │
│                                                              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │                 异步任务调度器                         │   │
│  │  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐ │   │
│  │  │Worker 1 │  │Worker 2 │  │Worker 3 │  │Worker 4 │ │   │
│  │  │ [queue] │  │ [queue] │  │ [queue] │  │ [queue] │ │   │
│  │  └────┬────┘  └────┬────┘  └────┬────┘  └────┬────┘ │   │
```

### 练习 4：任务取消

```rust
use tokio::{self, time::Duration};

#[tokio::main]
async fn main() {
    // 创建一个可以被取消的任务
    let handle = tokio::spawn(async {
        for i in 0..100 {
            println!("任务执行中: {}", i);
            tokio::time::sleep(Duration::from_millis(200)).await;
        }
        "完成"
    });

    // 主任务等待 1 秒后取消
    tokio::time::sleep(Duration::from_secs(1)).await;
    
    println!("发送取消信号...");
    handle.abort();
    
    let result = handle.await;
    match result {
        Ok(v) => println!("任务正常完成: {}", v),
        Err(e) if e.is_cancelled() => println!("任务被取消"),
        Err(e) => println!("错误: {:?}", e),
    }
}
```

## 今日感悟

### 1. Tokio 把复杂的事情隐藏了

`#[tokio::main]` 一行背后是：多线程运行时构建、任务队列管理、Waker 注册、I/O 多路复用……但我们只需要写 `async fn`，Tokio 替我们搞定一切。

### 2. spawn 与 spawn_blocking 的选择是性能关键

在生产代码中，如果把 CPU 密集任务用 `spawn` 放到异步线程池，会导致整个线程池被占住，其他任务无法推进。`spawn_blocking` 把这类任务隔离到专用线程，保持异步线程池的高效。

### 3. Tokio 的调度比我想的更智能

通过任务窃取（work stealing），Tokio 保证即使某些任务运行时间很长，其他线程也不会闲着。这比自己手写的简单轮询调度要复杂得多，但 Tokio 已经帮你做好了。

### 4. 理解运行时的嵌套边界很重要

在已有 Tokio 运行时中，尽量不要再创建 multi-thread 运行时，这会导致线程爆炸。但创建 `current_thread` 运行时是可以的，用于隔离某些任务。

### 5. 超时和取消是异步编程的必备技能

`timeout` 和 `AbortHandle` 是控制异步任务生命周期的重要工具，生产代码中几乎总是需要处理超时场景，防止任务永远挂起。
