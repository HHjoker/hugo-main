## 为什么测试很重要？

在开始写测试代码之前，先理解为什么测试如此重要：

1. **防止回归** - 确保新代码不会破坏已有功能
2. **文档作用** - 测试用例展示了代码应该如何被使用
3. **设计反馈** - 难以测试的代码通常设计有问题
4. **重构信心** - 有了测试，重构时更有底气
5. **捕获边界情况** - 强制思考各种输入场景

Rust 内置了强大的测试支持，让编写和运行测试变得非常简单。

## 测试基础概念

### 测试函数的结构

Rust 中的测试函数有三个特点：

1. 使用 `#[test]` 属性标记
2. 没有参数和返回值
3. 通常放在 `tests` 模块或 `tests/` 目录中

```rust
#[cfg(test)]
mod tests {
    #[test]
    fn test_addition() {
        // 测试代码
        let result = 2 + 2;
        assert_eq!(result, 4);
    }
}
```

### 运行测试

```bash
# 运行所有测试
cargo test

# 运行特定测试
cargo test test_addition

# 运行包含某字符串的测试
cargo test addition

# 并行运行测试（默认）
cargo test -- --test-threads=4

# 串行运行测试
cargo test -- --test-threads=1

# 显示测试输出
cargo test -- --nocapture

# 只运行失败的测试
cargo test -- --failed

# 运行测试并生成覆盖率报告（需要 cargo-tarpaulin）
cargo tarpaulin
```

## 单元测试（Unit Tests）

单元测试用于测试单个函数或方法的行为。

### 基础单元测试

```rust
// src/lib.rs 或 src/main.rs

pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

pub fn multiply(a: i32, b: i32) -> i32 {
    a * b
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_add_positive_numbers() {
        assert_eq!(add(2, 3), 5);
        assert_eq!(add(10, 20), 30);
    }

    #[test]
    fn test_add_negative_numbers() {
        assert_eq!(add(-2, -3), -5);
        assert_eq!(add(-10, 20), 10);
    }

    #[test]
    fn test_add_zero() {
        assert_eq!(add(0, 5), 5);
        assert_eq!(add(5, 0), 5);
        assert_eq!(add(0, 0), 0);
    }

    #[test]
    fn test_multiply() {
        assert_eq!(multiply(3, 4), 12);
        assert_eq!(multiply(-2, 3), -6);
        assert_eq!(multiply(0, 100), 0);
    }
}
```

### 测试私有函数

单元测试可以访问同一模块中的私有函数：

```rust
// src/lib.rs

fn private_helper(x: i32) -> i32 {
    x * 2
}

pub fn public_api(x: i32) -> i32 {
    private_helper(x) + 1
}

#[cfg(test)]
mod tests {
    use super::*;

    // 可以直接测试私有函数！
    #[test]
    fn test_private_helper() {
        assert_eq!(private_helper(5), 10);
        assert_eq!(private_helper(-3), -6);
    }

    #[test]
    fn test_public_api() {
        assert_eq!(public_api(5), 11);
    }
}
```

### 测试 Result 和 Option

```rust
pub fn divide(a: i32, b: i32) -> Result<i32, String> {
    if b == 0 {
        Err("除数不能为零".to_string())
    } else {
        Ok(a / b)
    }
}

pub fn find_first_even(numbers: &[i32]) -> Option<i32> {
    numbers.iter().find(|&&x| x % 2 == 0).copied()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_divide_success() {
        let result = divide(10, 2);
        assert_eq!(result, Ok(5));
    }

    #[test]
    fn test_divide_by_zero() {
        let result = divide(10, 0);
        assert!(result.is_err());
        assert_eq!(result.unwrap_err(), "除数不能为零");
    }

    #[test]
    fn test_find_first_even_found() {
        let numbers = vec![1, 3, 5, 8, 9];
        let result = find_first_even(&numbers);
        assert_eq!(result, Some(8));
    }

    #[test]
    fn test_find_first_even_not_found() {
        let numbers = vec![1, 3, 5, 7, 9];
        let result = find_first_even(&numbers);
        assert_eq!(result, None);
    }

    // 使用 ? 运算符简化 Result 测试
    #[test]
    fn test_divide_with_question_mark() -> Result<(), String> {
        let result = divide(15, 3)?;
        assert_eq!(result, 5);
        Ok(())
    }
}
```

## 常用断言宏

Rust 提供了多种断言宏来帮助编写测试：

### assert! - 基础断言

```rust
#[test]
fn test_assert_macro() {
    let is_valid = true;
    assert!(is_valid);
    
    let is_empty = false;
    assert!(!is_empty);
    
    // 自定义错误消息
    let value = 5;
    assert!(value > 0, "value 应该是正数，但实际是 {}", value);
}
```

### assert_eq! 和 assert_ne! - 相等性断言

```rust
#[test]
fn test_equality_assertions() {
    let a = 5;
    let b = 5;
    let c = 10;
    
    assert_eq!(a, b);        // 断言相等
    assert_ne!(a, c);        // 断言不相等
    
    // 自定义错误消息
    assert_eq!(a, b, "a 和 b 应该相等，但 a={} b={}", a, b);
    
    // 可以比较复杂类型
    let vec1 = vec![1, 2, 3];
    let vec2 = vec![1, 2, 3];
    assert_eq!(vec1, vec2);
    
    let str1 = "hello";
    let str2 = "hello";
    assert_eq!(str1, str2);
}
```

### assert!(result.is_ok()) / assert!(result.is_err())

```rust
#[test]
fn test_result_assertions() {
    let result: Result<i32, &str> = Ok(5);
    
    assert!(result.is_ok());
    assert!(!result.is_err());
    
    let err_result: Result<i32, &str> = Err("error");
    assert!(err_result.is_err());
}
```

### panic! - 测试期望的 panic

```rust
pub fn dangerous_function(should_panic: bool) {
    if should_panic {
        panic!("这是预期的 panic！");
    }
}

#[test]
#[should_panic(expected = "这是预期的 panic！")]
fn test_expected_panic() {
    dangerous_function(true);
}

#[test]
fn test_no_panic() {
    // 这个测试不应该 panic
    dangerous_function(false);
}
```

## 集成测试（Integration Tests）

集成测试用于测试整个库或应用的公共 API，位于 `tests/` 目录中。

### 项目结构

```
my_project/
├── Cargo.toml
├── src/
│   └── lib.rs
└── tests/
    ├── integration_test.rs
    └── another_test.rs
```

### 集成测试示例

```rust
// tests/integration_test.rs

use my_project::*;  // 使用库的公共 API

#[test]
fn test_public_api_integration() {
    // 测试公共 API 的组合使用
    let result = add(2, 3);
    let final_result = multiply(result, 2);
    assert_eq!(final_result, 10);
}

#[test]
fn test_multiple_functions() {
    // 测试多个函数的协作
    let numbers = vec![1, 2, 3, 4, 5];
    let sum: i32 = numbers.iter().sum();
    let avg = sum / numbers.len() as i32;
    assert_eq!(avg, 3);
}
```

### 集成测试最佳实践

```rust
// tests/common/mod.rs

// 可以在 tests/common/mod.rs 中定义共享的测试工具
// 注意：这个模块不会被自动识别为测试

pub fn setup_test_data() -> Vec<i32> {
    vec![1, 2, 3, 4, 5]
}

pub fn cleanup() {
    // 清理测试资源
}
```

```rust
// tests/integration_test.rs

mod common;  // 引入共享模块

use my_project::*;
use crate::common::setup_test_data;

#[test]
fn test_with_shared_setup() {
```

## 实战：完整测试示例

### 被测试的代码

```rust
// src/lib.rs

/// 一个简单的计算器模块
pub mod calculator {
    pub fn add(a: i32, b: i32) -> i32 {
        a + b
    }

    pub fn subtract(a: i32, b: i32) -> i32 {
        a - b
    }

    pub fn multiply(a: i32, b: i32) -> i32 {
        a * b
    }

    pub fn divide(a: i32, b: i32) -> Result<i32, String> {
        if b == 0 {
            Err("除数不能为零".to_string())
        } else {
            Ok(a / b)
        }
    }

    pub fn power(base: i32, exp: u32) -> i32 {
        base.pow(exp)
    }

    pub fn factorial(n: u32) -> Result<u32, String> {
        if n > 20 {
            Err("n 太大，会导致溢出".to_string())
        } else {
            Ok((1..=n).product())
        }
    }
}

/// 字符串工具模块
pub mod string_utils {
    pub fn reverse(s: &str) -> String {
        s.chars().rev().collect()
    }

    pub fn is_palindrome(s: &str) -> bool {
        let cleaned: String = s
            .chars()
            .filter(|c| c.is_alphanumeric())
            .collect::<String>()
            .to_lowercase();
        
        cleaned == cleaned.chars().rev().collect::<String>()
    }

    pub fn count_words(s: &str) -> usize {
        s.split_whitespace().count()
    }
}
```

## 关键概念理解

### 1. #[cfg(test)] 的作用

```rust
// 这段代码只在运行测试时才会被编译
#[cfg(test)]
mod tests {
    // 测试代码
}

// cfg 属性可以条件编译代码
#[cfg(debug_assertions)]
fn debug_only_function() {
    println!("Debug mode only");
}

#[cfg(not(test))]
fn production_only_function() {
    println!("Only in production builds");
}
```

### 2. 测试执行顺序

```rust
#[test]
fn test_a() {
    println!("Test A");
}

#[test]
fn test_b() {
    println!("Test B");
}

#[test]
fn test_c() {
    println!("Test C");
}

// 默认情况下，测试并行执行，顺序不确定
// 使用 --test-threads=1 可以串行执行
```

### 3. 测试隔离

每个测试函数都是独立的：

```rust
static mut COUNTER: i32 = 0;

#[test]
fn test_1() {
    unsafe {
        COUNTER += 1;
    }
    // 不要依赖其他测试的状态！
}

#[test]
fn test_2() {
    // COUNTER 的值是不确定的，因为测试可能并行执行
    // 每个测试应该是独立的
}
```

### 4. 忽略测试

```rust
#[test]
#[ignore]
fn test_slow_operation() {
    // 这个测试默认不会运行
    std::thread::sleep(std::time::Duration::from_secs(10));
}

// 运行被忽略的测试
// cargo test -- --ignored

// 运行所有测试（包括被忽略的）
// cargo test -- --include-ignored
```

### 练习 3：测试应该 panic 的情况

编写一个函数，当输入无效时应该 panic，并为它编写测试：

<summary>参考答案</summary>

```rust
pub fn get_first<T: Clone>(vec: &[T]) -> T {
    if vec.is_empty() {

#[cfg(test)]
mod tests {

    fn test_get_first_success() {
```

## 今日感悟

今天正式开始学习 Rust 的测试系统，有几个深刻的体会：

**测试是 Rust 的一等公民**：与其他语言需要额外配置测试框架不同，Rust 内置了完整的测试支持。`#[test]` 属性、断言宏、`cargo test` 命令，一切都开箱即用。这种设计让写测试变得非常简单，几乎没有门槛。

**单元测试可以访问私有函数**：这一点很赞！在很多语言中，测试私有函数需要特殊技巧或者根本做不到。但 Rust 允许测试模块访问同一模块中的所有内容，这意味着我们可以测试内部实现细节，而不仅仅是公共 API。这对于确保复杂内部逻辑的正确性很有帮助。

**断言宏的智能输出**：`assert_eq!` 和 `assert_ne!` 在失败时会显示两个值的差异，这对于调试非常有帮助。不需要手动拼接错误消息就能看到问题所在。

**测试隔离的重要性**：每个测试都应该是独立的，不依赖其他测试的状态。这意味着不能依赖全局变量或者测试执行顺序。这个约束虽然严格，但能写出更健壮的测试。

**集成测试与单元测试的分工**：单元测试关注内部逻辑，集成测试关注公共 API 的组合使用。两者互补，共同保证代码质量。

明天将继续深入学习测试进阶内容，包括参数化测试和覆盖率分析。测试是保证代码质量的重要手段，值得投入时间深入学习。
