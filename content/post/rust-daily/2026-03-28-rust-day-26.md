## 核心概念深度梳理

### 1. Option<T> 完整用法

#### 1.1 创建 Option

```rust
// 显式创建
let some_value: Option<i32> = Some(42);
let no_value: Option<i32> = None;

// 函数返回 Option
fn find_user(id: u32) -> Option<User> {
    // 找到返回 Some(user)，否则 None
}

// 方法链返回 Option
let first_char = text.chars().next();  // Option<char>
let value = map.get("key");            // Option<&V>
```

#### 1.2 解包 Option 的 5 种方式

```rust
let opt: Option<i32> = Some(42);

// 方式 1: match (最完整)
match opt {
    Some(val) => println!("值：{}", val),
    None => println("无值"),
}

// 方式 2: if let (简洁)
if let Some(val) = opt {
    println!("值：{}", val);
}

// 方式 3: unwrap (可能 panic)
let val = opt.unwrap();  // None 时 panic!

// 方式 4: unwrap_or (提供默认值)
let val = opt.unwrap_or(0);  // None 时返回 0

// 方式 5: unwrap_or_else (延迟计算默认值)
let val = opt.unwrap_or_else(|| {
    println!("使用默认值");
    0
});
```

#### 1.3 Option 常用方法

```rust
let opt: Option<i32> = Some(42);

// 映射
let doubled = opt.map(|x| x * 2);           // Option<i32>
let flattened = opt.and_then(|x| Some(x * 2)); // Option<i32>

// 过滤
let filtered = opt.filter(|x| *x > 40);     // Option<i32>

// 组合
let combined = opt.or(Some(0));             // Option<i32>

// 检查
let is_some = opt.is_some();                // bool
let is_none = opt.is_none();                // bool

// 转换为 Result
let result: Result<i32, &str> = opt.ok_or("无值");
```

### 2. Result<T, E> 完整用法

#### 2.1 创建 Result

```rust
// 显式创建
let success: Result<i32, &str> = Ok(42);
let failure: Result<i32, &str> = Err("出错了");

// 函数返回 Result
fn divide(a: i32, b: i32) -> Result<i32, DivError> {
    if b == 0 {
        Err(DivError::DivideByZero)
    } else {
        Ok(a / b)
    }
}

// 标准库函数
let content = fs::read_to_string("file.txt");  // Result<String, io::Error>
let parsed = "42".parse::<i32>();              // Result<i32, ParseIntError>
```

#### 2.2 解包 Result 的 6 种方式

```rust
let res: Result<i32, &str> = Ok(42);

// 方式 1: match (最完整，推荐)
match res {
    Ok(val) => println!("成功：{}", val),
    Err(e) => println!("错误：{}", e),
}

// 方式 2: if let (只处理成功)
if let Ok(val) = res {
    println!("成功：{}", val);
}

// 方式 3: unwrap (可能 panic)
let val = res.unwrap();  // Err 时 panic!

// 方式 4: expect (带消息的 panic)
let val = res.expect("期望操作成功");

// 方式 5: unwrap_or (提供默认值)
let val = res.unwrap_or(0);  // Err 时返回 0

// 方式 6: ? 运算符 (传播错误)
fn caller() -> Result<i32, &str> {
    let val = res?;  // Err 时直接返回
    Ok(val * 2)
}
```

#### 2.3 Result 常用方法

```rust
let res: Result<i32, &str> = Ok(42);

// 映射
let doubled = res.map(|x| x * 2);           // Result<i32, &str>
let mapped_err = res.map_err(|e| e.len());  // Result<i32, usize>

// 扁平映射
let flattened = res.and_then(|x| Ok(x * 2)); // Result<i32, &str>

// 检查
let is_ok = res.is_ok();                    // bool
let is_err = res.is_err();                  // bool

// 获取值（引用）
let val_ref = res.as_ref();                 // Result<&i32, &str>
let val_mut = res.as_mut();                 // Result<&mut i32, &str>

// 转换为 Option
let opt = res.ok();                         // Option<i32>
let opt_err = res.err();                    // Option<&str>

// 组合
let combined = res.or(Ok(0));               // Result<i32, &str>
```

### 3. ? 运算符详解

#### 3.1 基本用法

```rust
// 在返回 Result 的函数中
fn read_config() -> Result<Config, io::Error> {
    let file = File::open("config.txt")?;  // Err 时直接返回
    let content = read_to_string(file)?;   // Err 时直接返回
    let config = parse(content)?;          // Err 时直接返回
    Ok(config)
}

// 等价于
fn read_config_verbose() -> Result<Config, io::Error> {
    let file = match File::open("config.txt") {
        Ok(f) => f,
        Err(e) => return Err(e),
    };
    
    let content = match read_to_string(file) {
        Ok(c) => c,
        Err(e) => return Err(e),
    };
    
    let config = match parse(content) {
        Ok(c) => c,
        Err(e) => return Err(e),
    };
    
    Ok(config)
}
```

#### 3.2 ? 与 From trait

```rust
// ? 会自动调用 From::from 进行类型转换
fn process() -> Result<(), AppError> {
    let file = File::open("data.txt")?;  // io::Error -> AppError
    let content = read_to_string(file)?; // io::Error -> AppError
    let parsed = content.parse::<i32>()?; // ParseIntError -> AppError
    Ok(())
}

// 需要实现 From trait
impl From<io::Error> for AppError {
    fn from(err: io::Error) -> Self {
        AppError::Io(err)
    }
}

impl From<ParseIntError> for AppError {
    fn from(err: ParseIntError) -> Self {
        AppError::Parse(err)
    }
}
```

#### 3.3 ? 在 Option 中的使用

```rust
// ? 也可以用于 Option
fn get_first_char(text: &str) -> Option<char> {
    let first = text.chars().next()?;  // None 时直接返回 None
    Some(first.to_ascii_uppercase())
}

// 等价于
fn get_first_char_verbose(text: &str) -> Option<char> {
    match text.chars().next() {
        Some(c) => Some(c.to_ascii_uppercase()),
        None => return None,
    }
}
```

### 4. 自定义错误类型

#### 4.1 错误类型设计原则

```rust
// ✅ 好的错误类型设计
#[derive(Debug)]
pub enum AppError {
    // 按子系统分类
    Config(ConfigError),
    Database(DatabaseError),
    Network(NetworkError),
    Validation(ValidationError),
    
    // 包含足够的上下文
    FileNotFound { path: String, operation: String },
    PermissionDenied { path: String, user: String },
    
    // 支持错误链
    Io(io::Error),
    Json(serde_json::Error),
}

// ❌ 不好的错误类型设计
#[derive(Debug)]
pub enum BadError {
    Error1,      // 没有上下文
    Error2,      // 没有区分
    String(String), // 类型擦除，丢失信息
}
```

#### 4.2 实现 Error trait

```rust
use std::fmt;
use std::error::Error;

#[derive(Debug)]
pub enum AppError {
    Config(String),
    Io(io::Error),
}

// Display 实现（必需）
impl fmt::Display for AppError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            AppError::Config(msg) => write!(f, "配置错误：{}", msg),
            AppError::Io(err) => write!(f, "IO 错误：{}", err),
        }
    }
}

// Error trait 实现（推荐）
impl Error for AppError {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        match self {
            AppError::Config(_) => None,
            AppError::Io(err) => Some(err),
        }
    }
}

// From 实现（方便转换）
impl From<io::Error> for AppError {
    fn from(err: io::Error) -> Self {
        AppError::Io(err)
    }
}
```

#### 4.3 使用 thiserror 简化

```rust
use thiserror::Error;

#[derive(Error, Debug)]
pub enum AppError {
    #[error("配置错误：{0}")]
    Config(String),
    
    #[error("IO 错误")]
    Io(#[from] io::Error),  // 自动实现 From
    
    #[error("文件 {path} 未找到")]
    FileNotFound { path: String },
    
    #[error("操作 {operation} 失败：{source}")]
    OperationFailed {
        operation: String,
        #[source]
        source: Box<dyn Error + 'static>,
    },
}
```

## 错误处理最佳实践清单

### ✅ DO - 应该做的

#### 1. 使用具体的错误类型

```rust
// ✅ 好：具体的错误类型
#[derive(Debug)]
enum DatabaseError {
    ConnectionFailed(String),
    QueryFailed { sql: String, reason: String },
    Timeout(Duration),
}

// ❌ 差：过于泛化
type DatabaseError = String;
```

#### 2. 提供足够的上下文

```rust
// ✅ 好：包含上下文
Err(ProcessError::FileNotFound {
    path: "/data/config.json".to_string(),
    operation: "读取配置".to_string(),
})

// ❌ 差：信息不足
Err("文件未找到".to_string())
```

#### 3. 使用 ? 运算符传播错误

```rust
// ✅ 好：简洁清晰
fn load_user(id: u32) -> Result<User, AppError> {
    let conn = connect()?;
    let row = query(&conn, id)?;
    Ok(parse_user(row)?)
}

// ❌ 差：冗长重复
fn load_user(id: u32) -> Result<User, AppError> {
    let conn = match connect() {
        Ok(c) => c,
        Err(e) => return Err(e),
    };
    let row = match query(&conn, id) {
        Ok(r) => r,
        Err(e) => return Err(e),
    };
    // ...
}
```

#### 4. 在边界处处理错误

```rust
// ✅ 好：在 main 中统一处理
fn main() {
    match run() {
        Ok(_) => println!("完成"),
        Err(e) => {
            eprintln!("错误：{}", e);
            std::process::exit(1);
        }
    }
}

fn run() -> Result<(), AppError> {
    // 业务逻辑，使用 ? 传播错误
}

// ❌ 差：到处 unwrap
fn main() {
    run().unwrap();  // panic 时没有友好消息
}
```

#### 5. 区分可恢复和不可恢复错误

```rust
// ✅ 可恢复错误：用 Result
fn parse_config(content: &str) -> Result<Config, ParseError> {
    // 配置格式错误，调用者可以修复
}

// ✅ 不可恢复错误：用 panic!
fn init_logger() {
    // 日志系统初始化失败，程序无法继续
    logging::init().expect("日志系统必须可用");
}
```

#### 6. 实现 From trait 方便转换

```rust
// ✅ 好：自动转换
impl From<io::Error> for AppError {
    fn from(err: io::Error) -> Self {
        AppError::Io(err)
    }
}

// 使用 ? 时自动转换
fn read_file() -> Result<String, AppError> {
    let content = fs::read_to_string("file.txt")?;  // 自动转换
    Ok(content)
}
```

#### 7. 使用 ResultExt 添加上下文

```rust
// ✅ 好：添加上下文
trait ResultExt<T, E> {
    fn context(self, msg: &str) -> Result<T, AppError>;
}

impl<T, E: std::error::Error> ResultExt<T, E> for Result<T, E> {
    fn context(self, msg: &str) -> Result<T, AppError> {
        self.map_err(|e| AppError::WithContext {
            message: msg.to_string(),
            source: Box::new(e),
        })
    }
}

// 使用
let content = fs::read_to_string("config.txt")
    .context("读取配置文件失败")?;
```

### ❌ DON'T - 不应该做的

#### 1. 避免滥用 unwrap

```rust
// ❌ 差：可能 panic
let file = File::open("config.txt").unwrap();

// ✅ 好：处理错误
let file = match File::open("config.txt") {
    Ok(f) => f,
    Err(e) => return Err(AppError::Config(format!("无法打开配置文件：{}", e))),
};

// 或者在测试/原型中使用
let file = File::open("config.txt").expect("配置文件必须存在");
```

#### 2. 不要隐藏错误

```rust
// ❌ 差：隐藏错误信息
fn process() -> Result<(), ()> {
    // 调用者不知道发生了什么错误
}

// ✅ 好：传递错误信息
fn process() -> Result<(), ProcessError> {
    // 调用者可以了解具体错误
}
```

#### 3. 不要使用 String 作为错误类型

```rust
// ❌ 差：类型擦除
type Error = String;

fn parse() -> Result<i32, String> {
    Err("解析失败".to_string())  // 丢失了原始错误类型
}

// ✅ 好：保留类型信息
#[derive(Debug)]
enum ParseError {
    InvalidFormat(String),
    OutOfRange { value: String, min: i32, max: i32 },
}

fn parse() -> Result<i32, ParseError> {
    Err(ParseError::InvalidFormat("期望数字".to_string()))
}
```

#### 4. 不要在库代码中 panic

```rust
// ❌ 差：库代码中 panic
pub fn get_item(vec: &Vec<i32>, index: usize) -> i32 {
    vec[index]  // 可能 panic
}

// ✅ 好：返回 Option 或 Result
pub fn get_item(vec: &Vec<i32>, index: usize) -> Option<i32> {
    vec.get(index).copied()
}

pub fn get_item_result(vec: &Vec<i32>, index: usize) -> Result<i32, IndexError> {
    vec.get(index)
        .copied()
        .ok_or(IndexError::OutOfBounds { index, len: vec.len() })
}
```

#### 5. 不要忽略错误

```rust
// ❌ 差：忽略错误
let _ = File::create("log.txt");  // 创建失败也不知道

// ✅ 好：至少记录
if let Err(e) = File::create("log.txt") {
    eprintln!("警告：无法创建日志文件：{}", e);
}
```

## 常见问题解答

### Q1: 什么时候用 panic!，什么时候用 Result？

**A:** 遵循以下原则：

| 场景 | 选择 | 理由 |
|------|------|------|
| 程序状态已损坏 | `panic!` | 无法安全继续 |
| 违反不变量 | `panic!` | 这是 bug，不是预期错误 |
| 用户输入错误 | `Result` | 可恢复，用户可修正 |
| 文件/网络错误 | `Result` | 外部环境问题，可处理 |
| 配置错误 | `Result` | 可回退到默认值 |
| 除零 | `panic!` (Release) | 逻辑错误 |
| 数组越界 | `panic!` | 逻辑错误 |

```rust
// panic! 的场景
pub fn new_user(name: &str, age: u32) -> User {
    assert!(!name.is_empty(), "用户名不能为空");  // 这是 API  misuse
    assert!(age < 150, "年龄不合理");  // 违反不变量
    User { name: name.to_string(), age }
}

// Result 的场景
pub fn load_user(id: u32) -> Result<User, DatabaseError> {
    // 用户可能不存在，这是预期情况
    database::find(id)
}
```

### Q2: Box<dyn Error> 和自定义枚举哪个更好？

**A:** 各有优劣：

```rust
// Box<dyn Error> - 简单快速
// ✅ 优点：代码少，快速原型
// ❌ 缺点：类型擦除，难以匹配处理
type AppError = Box<dyn std::error::Error>;

fn process() -> Result<(), AppError> {
    let file = File::open("data.txt")?;  // 自动转换
    Ok(())
}

// 自定义枚举 - 生产推荐
// ✅ 优点：类型安全，可匹配处理，文档化
// ❌ 缺点：代码多，需要维护
#[derive(Debug)]
enum AppError {
    Io(io::Error),
    Parse(ParseIntError),
    Config(String),
}

impl From<io::Error> for AppError { /* ... */ }
impl From<ParseIntError> for AppError { /* ... */ }

fn process() -> Result<(), AppError> {
    let file = File::open("data.txt")?;
    Ok(())
}

// 最佳实践：库用枚举，应用可用 anyhow
// 库：暴露具体错误类型
// 应用：用 anyhow 简化
```

### Q3: ? 运算符只能在 fn 返回 Result 时使用吗？

**A:** 主要是，但有例外：

```rust
// 标准情况
fn returns_result() -> Result<i32, io::Error> {
    let file = File::open("test.txt")?;  // ✅
    Ok(42)
}

// Option 也可以
fn returns_option() -> Option<i32> {
    let text = Some("hello");
    let first = text?.chars().next()?;  // ✅
    Some(first as i32)
}

// main 函数（Rust 1.26+）
fn main() -> Result<(), io::Error> {
    let file = File::open("test.txt")?;  // ✅
    Ok(())
}

// ❌ 不行：返回类型不匹配
fn returns_i32() -> i32 {
    let file = File::open("test.txt")?;  // 编译错误
    42
}
```

### Q4: 如何处理多个可能的错误类型？

**A:** 三种方案：

```rust
// 方案 1: 自定义枚举（推荐用于库）
#[derive(Debug)]
enum AppError {
    Io(io::Error),
    Parse(ParseIntError),
    Json(serde_json::Error),
}

// 方案 2: Box<dyn Error>（简单但类型擦除）
fn process() -> Result<(), Box<dyn std::error::Error>> {
    // 可以返回任何 Error 类型
}

// 方案 3: anyhow（推荐用于应用）
use anyhow::Result;

fn process() -> Result<()> {
    // 自动处理所有错误类型
}
```

### Q5: 如何在错误中添加堆栈跟踪？

**A:** 使用 backtrace 或 anyhow：

```rust
// 方法 1: 启用 RUST_BACKTRACE
// 运行程序前设置环境变量
// export RUST_BACKTRACE=1
// cargo run

// 方法 2: 使用 anyhow（自带堆栈跟踪）
use anyhow::{Context, Result};

fn process() -> Result<()> {
    let content = fs::read_to_string("file.txt")
        .context("读取文件失败")?;  // 包含位置信息
    Ok(())
}

// 错误输出会包含：
// Error: 读取文件失败
// 
// Caused by:
//     No such file or directory (os error 2)
// 
// Stack backtrace:
//    0: <E as anyhow::context::ext::StdError>::ext_context
//    1: anyhow::context::<impl anyhow::Context>::context
//    2: myapp::process
//    ...
```

fn read_number() -> i32 {

### 测试题 4：? 运算符

以下代码的输出是什么？

```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    let value: Option<i32> = None;
    let result = value?;
    println!("{}", result);
    Ok(())
}
```

<details>
<summary>点击查看答案</summary>

**答案**: 程序正常退出，无输出

**解析**: `None?` 在返回 `Option` 的上下文中会提前返回 `None`。但这里 `main` 返回 `Result<(), Error>`，所以 `None?` 会尝试转换为 `Result`。

实际上这段代码**不能编译**，因为 `?` 用于 `Option` 时，函数必须返回 `Option`。

**修复**:
```rust
fn main() -> Option<()> {
    let value: Option<i32> = None;
    let result = value?;  // 提前返回 None
    println!("{}", result);
    Some(())
}
```
</details>

### 测试题 5：错误处理策略

以下代码有什么问题？如何改进？

```rust
fn load_config() -> Config {
    let content = fs::read_to_string("config.json").unwrap();
    let config: Config = serde_json::from_str(&content).unwrap();
    config
}
```

<details>
<summary>点击查看答案</summary>

**问题**:
1. 使用 `unwrap()` 可能 panic
2. 没有错误处理
3. 调用者无法知道失败原因

**改进方案**:

```rust
#[derive(Debug)]
enum ConfigError {
    Io(io::Error),
    Parse(serde_json::Error),
}

impl From<io::Error> for ConfigError {
    fn from(err: io::Error) -> Self {
        ConfigError::Io(err)
    }
}

impl From<serde_json::Error> for ConfigError {
    fn from(err: serde_json::Error) -> Self {
        ConfigError::Parse(err)
    }
}

fn load_config() -> Result<Config, ConfigError> {
    let content = fs::read_to_string("config.json")?;
    let config = serde_json::from_str(&content)?;
    Ok(config)
}

// 在 main 中处理
fn main() {
    match load_config() {
        Ok(config) => run_app(config),
        Err(ConfigError::Io(e)) => {
            eprintln!("无法读取配置文件：{}", e);
            eprintln!("请确保 config.json 存在且可读");
        }
        Err(ConfigError::Parse(e)) => {
            eprintln!("配置文件格式错误：{}", e);
            eprintln!("请检查 JSON 格式是否正确");
        }
    }
}
```
</details>
